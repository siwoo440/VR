# 화면 구상

Atelier | Verse의 웹 화면(페이지)을 어떤 구성으로 만들지 정리한 문서입니다. 2026년 10월 8일 기준입니다.

- 이 문서와 `design/` 폴더는 화면 구상을 다룹니다. 3D와 VR 구현은 `unity/` 폴더의 Unity 프로젝트에서 진행합니다.
- 구현 방식은 2026-10-08에 "Unity 앱 하나로 PC와 VR 모두"로 정해졌습니다. 에디터와 방 안은 앱 안의 화면이고, 시안은 그 배치와 문구의 기준입니다.
- `design/`의 화면은 동작하지 않는 시안이며, 이름·숫자·금액은 모두 예시입니다.

---
## 1. 화면 사이의 흐름

```text
시작하기 → 처음 안내 → 내 작업실 ─┬─ 에디터 ─ 걸어 보기 ─→ 방 안
                                  ├─ 초대받은 방 ───────────→ 방 안
                                  └─ 초대 링크 만들기

둘러보기 ─ 검색 ─→ 맵 상세 ─ 새 방 열기 / 열린 방 입장 ─→ 방 안
소식 ─ 알림 ─ 메시지 ───── 따라가기 / 초대 수락 ─────→ 방 안
상점 ─ 구독          프로필 ─ 설정          (운영자) 신고 처리
```

로그인한 뒤 첫 화면은 내 작업실입니다. 방 안으로 들어가는 길은 "링크(앱 실행) 또는 방 코드"와 "맵 상세" 두 가지입니다. VR 기기에서는 방 코드를 씁니다.

## 3. 화면을 만드는 규칙

- **누르기 크기**: 손가락으로 누르는 화면에서는 버튼·칩·색 고르기를 44px 이상으로 합니다. 글 안의 링크는 예외입니다.
- **탭**: 탭과 내용을 짝지어 낭독기가 읽을 수 있게 하고, 좌우 방향키로 옮길 수 있게 합니다. `shell.js`가 자동으로 연결합니다.
- **상태 안내**: 내용이 없거나 문제가 생기면 무엇이 일어났는지와 다음에 할 일을 함께 적습니다. `states.html`의 문구를 기준으로 합니다.
- **이후 단계의 기능**: 비활성 버튼이나 단계 표시로 나타내고, 되는 것처럼 보이게 만들지 않습니다.
- **서비스 이름**: 번역하지 않도록 표시합니다.
- **넘침**: 휴대폰(375px), 태블릿(820px), PC(1360px) 너비에서 가로로 넘치지 않아야 합니다.

2026-10-08에 19개 화면을 위 기준으로 자동 확인했습니다. 실제 휴대폰과 VR 기기에서는 아직 열어 보지 않았습니다.

## 4. 앱 화면과 웹 화면

구현 방식이 Unity 앱으로 정해져 화면이 두 종류로 나뉩니다. 아래 구분은 가안이며, 내 작업실과 둘러보기를 어디에 둘지는 아직 정하지 않았습니다.

| 종류 | 화면 | 시안의 쓰임 |
| --- | --- | --- |
| 앱 안의 화면 | 에디터, 방 안, 설정의 화면·조작·VR 부분 | 배치와 문구의 기준. Unity에서 다시 만든다 |
| 웹 화면 | 시작하기, 처음 안내, 둘러보기, 검색, 맵 상세, 소식, 알림, 메시지, 상점, 구독, 프로필, 신고 처리 | 그대로 구현의 기준 |
| 정하지 않음 | 내 작업실 | 앱의 첫 화면으로 둘지 웹에 둘지 결정 필요 |

### 4.1 앱 안의 게임 화면 (Unity 2일차)

방 안에서 보는 화면은 Unity에서 직접 만들기 시작했습니다. 로블록스와 VRChat의 화면을 섞는다는 결정(2026-10-08)에 따라 다음과 같이 나눴습니다. 색과 모서리, 어긋난 그림자는 웹 시안의 토큰을 그대로 옮겼습니다.

| 화면 요소 | 따온 곳 | 내용 | 대응하는 웹 시안 |
| --- | --- | --- | --- |
| 왼쪽 위 메뉴 단추 | 로블록스 | 누르면 Esc 메뉴가 열림 | 방 안의 위쪽 띠 |
| 방 이름과 인원 | 두 곳 모두 | 접속 표시 점, 방 이름, 현재 인원/8 | 방 안의 방 정보 |
| 오른쪽 위 사람들 목록 | 로블록스 | 같은 방 사람들. Tab으로 켜고 끔 | 방 안의 참여자 |
| 아래 가운데 부품 칸 | 로블록스 | 9칸. 숫자 키로 고르고 같은 키로 풂 | 에디터의 부품 고르기 |
| 부품 칸 위 놓기 안내 | 로블록스 | 부품을 골랐을 때만 보임. 놓기·지우기·칠하기·되돌리기·다시 실행 키와 놓인 블록 수(3·5·6일차) | 에디터의 성능 상한 |
| 위 가운데 알림 띠 | - | 놓을 수 없는 까닭, 저장 실패, 읽지 못한 블록 수, 되돌릴 것 없음 같은 짧은 알림. 2.5초 뒤 사라짐(6일차) | 구성요소의 알림 띠 |
| 오른쪽 아래 걷기·날기 표시 | 마인크래프트 창작 모드 | V로 날기를 켜면 "날기"와 골드 점. 날 때는 Space 위·Shift 아래(7일차) | 에디터의 시점 전환 |
| 놓일 자리 미리 보기 | - | 조준한 칸에 반투명 블록. 놓을 수 없으면 붉은 흙색(3일차) | 에디터의 편집 화면 |
| 오른쪽 아래 저장 표시 | - | "저장했습니다", "저장 대기 중", "저장하지 못했습니다"처럼 자동 저장의 상태(4일차) | 에디터의 저장 상태 |
| 머리 위 이름표 | VRChat | 접속 표시 점과 이름. 3인칭에서 보임 | 구성요소의 캐릭터 |
| Esc 메뉴의 탭과 아래 큰 단추 | 로블록스 | 탭 4개(바로가기·사람들·설정·도움말), 끝내기·시작 위치로·돌아가기 | 설정, 방 안 |
| Esc 메뉴의 큰 타일 | VRChat | 시작 위치로, 시점 바꾸기. 내 작업실·맵 둘러보기·캐릭터·안전·신고는 "준비 중" | 내 작업실, 둘러보기, 프로필 |
| 시점 | 두 곳 모두 | 기본은 VRChat처럼 1인칭, 휠을 당기면 로블록스처럼 3인칭 | - |

아직 만들지 않은 것은 누를 수 없게 하고 "준비 중"으로 표시했습니다. 대화(채팅)는 여러 사람이 함께 들어오는 기능과 같이 만듭니다. VR에서는 같은 화면을 눈앞에 떠 있는 판으로 띄웁니다(12일차).

| 화면 요소 | VR에서(12·13일차, 가상 기기로만 확인) |
| --- | --- |
| 알림 띠 | 머리를 따라오는 판의 위쪽에 보임 |
| Esc 메뉴 | 왼손의 메뉴 단추로 눈앞 1.6m에 뜨고 그 자리에 머묾. 오른손에서 나가는 광선으로 가리키고 방아쇠로 누름 |
| 메뉴의 도움말, 설정, 시점 타일 | 도움말은 VR 조작 안내로 바뀌고, 시점 타일은 "PC 전용"으로 누를 수 없음 |
| 부품 칸, 놓인 블록 수, 걷기·날기 표시 | 왼손 위에 뜨는 부품 판에 보임. 오른손 광선으로 칸을 가리켜 고르고, 되돌리기와 다시 실행 단추도 여기에 있음(13일차) |
| 놓일 자리 미리 보기 | 오른손이 가리킨 칸에 PC와 같은 반투명 블록. 광선이 그 자리에서 끝남(13일차) |
| 메뉴 단추, 방 정보, 사람들 목록, 키 안내, 저장 표시 | 늘 보이지는 않음. 방 정보와 사람들 목록은 메뉴에서 볼 수 있음 |

2026-10-08에 바꾼 문구는 다음과 같습니다.

| 화면 | 바꾼 부분 |
| --- | --- |
| 방 안 | "VR로 입장"을 "VR 기기로 들어오기"로 바꾸고 방 코드 안내 추가 |
| 맵 상세, 초대 대화상자 | 링크는 앱을 여는 방식으로, VR 기기는 방 코드로 안내 |
| 상태 화면 | "앱이 설치되어 있지 않습니다" 안내 추가 |
| 시작하기, 처음 안내 | "링크나 방 코드로 초대" 문장 |

## 5. 아직 구상하지 않은 화면

- VR 기기 안에서 보는 화면 가운데 이동 표시와 채팅 보기. 메뉴와 알림은 12일차에, 부품 칸은 13일차에 만들었습니다(4.1절). 나머지는 여러 사람 접속 때 정합니다.
- 앱 설치 안내 화면과 앱 내려받기 화면. 배포 방법을 정한 뒤에 그립니다.
- 에디터의 세부 흐름: 빈 맵에서 시작하는 첫 안내, 저장 실패, 함께 고칠 때 겹치는 경우.
- 방 안의 세부 흐름: 내보내기 확인, 나갈 때 확인, 방장이 나간 경우.
- 결제 화면: 결제 수단과 환불 기준을 정한 뒤에 그립니다.
- 영어 화면.
- 홈페이지의 소개 페이지(`/atelier-verse.html`) 갱신: VR 문구가 아직 "검토하고 있습니다"입니다. 구현 방식이 정해지면 고칩니다.

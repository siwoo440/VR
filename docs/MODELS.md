# 3D 모델 목록

블록 말고 직접 만들어 넣을 3D 모델을 모두 모은 문서입니다. 2026년 10월 10일(Unity 23일차) 기준입니다.

지금 게임에 보이는 것은 모두 코드로 만든 도형입니다. 부품 다섯 가지(블록·판·기둥·경사·계단)는 코드가 모양을 만들고, 캐릭터·VR의 손·시작 위치 표식은 상자와 원기둥을 이어 붙인 임시 모양입니다. 이 문서는 그 자리에 넣을 모델과, 앞으로의 단계에서 필요해질 모델을 한곳에 적습니다.

- **무엇을 보고 적었나**: 지금의 코드(임시 도형으로 대신하고 있는 것), [`ROADMAP.md`](ROADMAP.md)와 [`BACKLOG.md`](BACKLOG.md), 화면 시안(`design/`의 에디터·프로필·상점·방 안), 사업 계획서 12번 탭(서비스 개요, 이용자 제작 콘텐츠 구조, 디자인 테마, 질문지의 그래픽·아바타 답).
- **표의 "근거" 칸**: `대체`는 지금 임시 도형으로 대신하고 있는 것, `로드맵`·`백로그`는 그 문서에 적힌 것, `시안`은 화면 시안에 이름이 나온 것, `기획`은 사업 계획서에 예로 나온 것, `제안`은 어디에도 없지만 제가 더한 것입니다. **`제안`은 빼셔도 됩니다.**
- **숫자는 가안입니다.** 크기와 삼각형 수는 지금의 코드와 캐릭터 크기에 맞춰 제가 정한 값이며, Quest 기기에서 재 본 값이 아닙니다.
- 맵 파일의 형식은 [`MAP-FORMAT.md`](MAP-FORMAT.md)에 있습니다.

## 2. 모델을 만들 때의 공통 규칙

게임에 넣었을 때 크기와 방향이 맞고, 놓고 칠하고 저장하는 지금의 기능이 그대로 듣게 하기 위한 규칙입니다.

### 2.1 길이와 방향

| 항목 | 규칙 | 까닭 |
| --- | --- | --- |
| 길이 | **표준 블록 한 변 = 1 = 1m**. 크기 조절(scale)은 1로 내보냅니다 | 맵의 모든 길이가 이 단위입니다(2026-10-09 결정) |
| 방향 | Unity에 넣었을 때 **위가 +Y, 앞이 +Z**, 회전은 0 | 캐릭터의 앞, 경사와 계단이 오르는 쪽이 +Z입니다 |
| 부품의 원점 | 모델을 **둘러싸는 상자의 가운데** | 맵 파일이 부품의 자리를 그 가운데로 적습니다 |
| 캐릭터의 원점 | 두 발 사이의 **바닥**(y = 0) | 지금의 캐릭터가 그렇습니다 |
| 손의 원점 | 손바닥 가운데(컨트롤러를 쥔 자리). 손가락 끝이 +Z, 손등이 +Y | 컨트롤러의 자세를 그대로 따릅니다 |
| 표식의 원점 | 바닥에 닿는 면의 가운데 | 바닥 위에 그대로 놓습니다 |

만드는 프로그램(Blender 등)마다 축이 달라 내보낼 때 설정이 필요합니다. 쓰시는 프로그램을 알려 주시면 내보내기 설정을 따로 적겠습니다.

### 2.2 부품의 크기

- 부품을 둘러싸는 상자의 **가로·높이·세로를 0.25의 배수**로 잡습니다. 맞추기 도우미가 1, 1/2, 1/4 단위로 맞추기 때문입니다.
- 모델은 그 상자를 **넘지 않게** 만듭니다. 상자를 꽉 채우지 않아도 되지만, 바닥에 놓이는 물건은 상자의 **바닥에 닿아야** 합니다(닿지 않으면 떠 보입니다).
- 한 부품은 4×4×4를 넘지 않게 합니다(가안). 맵의 바닥은 한 변 16~32, 높이는 12입니다.

### 2.3 캐릭터에 맞춘 치수

지금의 캐릭터 몸을 기준으로 합니다. 가구와 문의 크기를 정할 때 씁니다.

| 항목 | 값 |
| --- | --- |
| 몸의 높이(충돌) | 1.7 |
| 몸의 굵기(충돌) | 지름 0.6 |
| 눈높이 | 1.55 |
| 머리 꼭대기 | 1.74(머리 장식까지 1.85 이하) |
| 걸어서 오를 수 있는 턱 | 0.35 이하 |
| 뛰어오르는 높이 | 1.1 |

- 지나다니는 문은 뚫린 곳이 **폭 0.75 이상, 높이 1.875 이상**이어야 합니다.
- 걸어 오르는 계단은 한 단이 0.25입니다.
- 의자의 앉는 면은 0.5, 탁자의 윗면은 0.75가 어울립니다.

### 2.4 모양새와 색

- **블록·로우폴리**입니다(기획 질문지의 그래픽 방향 답). 면이 또렷하게 나뉜 각진 모양이며, 면마다 한 가지 색을 씁니다.
- 지금 부품의 모서리는 다듬지 않은 날카로운 모서리입니다. 새 모델도 같게 맞추는 것이 가안입니다(7절).
- 색은 "햇살 작업실" 테마의 색입니다.

| 색 | 값 | 지금의 부품 이름 |
| --- | --- | --- |
| 골드 | `#F7A71D` | `gold` |
| 블루 | `#025EE7` | `blue` |
| 테라코타 | `#B8440F` | `clay` |
| 잎 초록 | `#2B7A4B` | `leaf` |
| 아이보리 | `#FFFDF8` | `ivory` |
| 나무 | `#8E7F63` | `wood` |
| 잉크(눈, 다리 같은 짙은 곳) | `#1D2740` | 부품 색은 아님 |

- **색은 모델에 칠하지 않습니다.** 게임이 재질(색)을 입힙니다. 그래야 가운데 단추로 칠하기가 듣고, 색마다 모델을 따로 두지 않아도 됩니다.
- 모델의 면을 **재질 칸 둘까지**로 나눕니다(가안). 첫째 칸은 "칠하는 색"(이용자가 여섯 색에서 고르는 면), 둘째 칸은 "정해진 색"(의자의 다리, 나무의 줄기처럼 바뀌지 않는 면)입니다. 칸 하나로 충분하면 하나만 씁니다.
- 텍스처(그림을 입힌 면)는 쓰지 않는 것이 가안입니다. 종이 등불처럼 스스로 빛나야 하는 면은 따로 표시해 주시면 빛나는 재질을 입힙니다.

### 2.5 삼각형 수 (가안)

Quest에서 재 보기 전의 임시 상한입니다. 한 맵에 부품을 500개까지 놓을 수 있어, 부품 하나가 무거우면 맵 전체가 느려집니다.

| 모델 | 삼각형 수 |
| --- | --- |
| 구조 부품 | 200 이하(지금의 블록은 12, 계단은 36) |
| 꾸밈 부품 | 300 이하(나무처럼 큰 것은 600 이하) |
| 캐릭터 몸 한 벌 | 1,500 이하 |
| 머리 장식 | 300 이하 |
| 손 | 500 이하 |

둥근 모양은 원을 12~16각으로 나눕니다.

### 2.6 충돌하는 모양

- 상자 하나로 충분한 모델(의자, 탁자, 상자)은 따로 만들 것이 없습니다. 게임이 둘러싸는 상자로 막습니다.
- 상자 하나로는 어색한 모델(문틀, 아치, 경사)은 **단순한 충돌 모양**을 함께 만듭니다. 같은 파일 안에 `이름_col`이라는 이름으로 넣고, 상자 몇 개나 삼각형 수십 개의 단순한 모양으로 합니다.
- 캐릭터가 지나가야 하는 곳(문틀의 뚫린 곳)은 충돌 모양에서도 뚫려 있어야 합니다.

### 2.7 파일과 이름

- 파일 형식은 **FBX**가 가안입니다. Unity가 그대로 읽습니다. GLB는 읽는 꾸러미를 더 넣어야 하며, 3단계의 에셋 업로드(이용자가 올리는 GLB)를 만들 때 함께 정합니다(7절).
- 파일 하나에 모델 하나를 넣습니다. 조각이 여럿인 모델(캐릭터, 단추, 문)은 한 파일 안에 조각을 따로 둡니다.
- 파일 이름은 영문 소문자·숫자·밑줄로 적습니다(표의 "파일 이름").
- 넣는 곳은 `unity/Assets/_Project/Art/Models/` 아래의 묶음 폴더입니다(`Avatar`, `Hands`, `Parts`, `Markers`, `Sky`).
- **어디서 온 모델인지 적어 둡니다.** 직접 만든 것, 생성형 AI로 만든 것, 사거나 받은 것을 구분하고, 받은 것은 출처와 쓸 수 있는 조건을 함께 적습니다. 조건이 맞지 않는 모델은 넣지 않습니다.

## 3. 모델 목록

## 5. 모델을 넣으려면 코드에서 바꿔야 하는 것

모델 파일을 폴더에 넣는 것만으로는 게임에 나오지 않습니다. 아래를 함께 만들어야 합니다. 모델의 형식이 정해지면 일차로 잡아 진행합니다.

| 바꿀 것 | 지금 | 필요한 일 |
| --- | --- | --- |
| 부품의 모양 목록 | 모양이 다섯으로 정해져 있고 코드가 메시를 만듦(`PartShape`, `PartMeshes`) | 모델 파일의 메시를 부품 목록(`PartCatalog`)에 올리는 셋업. 부품마다 크기(둘러싸는 상자)를 적음 |
| 재질 칸 둘 | 부품 하나에 재질 하나 | "칠하는 색"과 "정해진 색"을 함께 입히기. 칠하기는 첫째 칸만 바꿈 |
| 색이 하나뿐인 부품 | 모든 부품이 모양 × 여섯 색 | 칠할 곳이 없는 소품(책 더미, 보드게임)은 한 가지로만 두기 |
| 부품의 작은 그림 | 모양 다섯의 윤곽을 코드로 그림 | 모델을 찍어 그림을 만드는 도구 |
| 부품 고르는 창 | 모양 다섯 × 색 여섯이 한 화면에 다 보임 | 부품이 늘면 갈래(구조·가구·식물…)와 쪽 넘기기가 필요(백로그에 있음) |
| 충돌 | 상자 하나 또는 메시 그대로 | 함께 만든 단순한 충돌 모양(`_col`) 쓰기 |
| 캐릭터 | 상자 열 개를 코드가 이어 붙임(`AvatarView`가 팔다리 넷을 흔듦) | 조각 모델로 바꾸고, 머리 장식을 붙이는 자리와 몸 색 바꾸기를 더함. 고른 캐릭터를 저장하는 것은 1-C |
| VR의 손 | 상자 하나 | 손 모델과, 가리킬 때·잡을 때 자세 바꾸기 |
| 빛나는 부품 | 없음 | 등불의 면을 빛나는 재질로. 실제로 둘레를 비추는 빛은 Quest에서 무거워 재 본 뒤 정함 |
| 움직이는 부품 | 없음 | 3단계 동작 규칙 전체 |
| 성능 | 블록 하나가 물체 하나, 상한 500개(임시) | 모델은 블록보다 삼각형이 많으므로 Quest에서 재서 상한을 다시 정함 |

- 맵 파일은 그대로 쓸 수 있습니다. 부품의 이름이 늘어나는 것은 판을 올리지 않습니다(`MAP-FORMAT.md` 2.3절). 다만 새 부품이 든 맵을 옛 판의 앱으로 열어 저장하면 그 부품이 사라집니다.
- 부품의 저장용 이름(`모양.색`)은 한 번 정하면 바꿀 수 없습니다. 모델을 처음 넣을 때 정합니다.

## 6. 만드는 순서 (권장)

1. **시험 모델 하나**(예: D-05 접이식 의자). 만들기 → 내보내기 → Unity에 넣기 → 놓고 칠하고 저장하기까지 한 번 끝까지 해 봅니다. 크기·방향·원점·재질 칸의 규칙(2절)이 맞는지 여기서 확인하고, 틀리면 규칙을 고칩니다. **여러 개를 한꺼번에 만들기 전에 꼭 먼저 합니다.**
2. **지금 임시 도형인 것**: 캐릭터(C-01~C-06), 시작 위치 표식(T-01), 나무(D-01), 얇은 판(S-02).
3. **구조 부품**(S-01, S-03~S-08): 건물을 짓는 데 가장 많이 쓰입니다.
4. **시안에 있는 꾸밈**(D-05~D-07).
5. **VR의 손**(H-01~H-03)과 순간 이동 표식(T-02): 실제 헤드셋으로 확인할 수 있게 된 뒤.
6. **제안한 것**에서 고르신 것.
7. 하늘(E), 움직이는 부품(M)은 그 기능을 만들 때.

| 무엇으로 만드는가(직접 만들기, 생성형 AI, 사거나 받기) | 정하지 않음 | 내보내기 설정, 출처와 사용 조건의 기록. 생성형 AI의 모델은 삼각형 수가 많고 면이 고르지 않아 다듬는 일이 필요할 수 있습니다 |
| 파일 형식 | FBX | GLB로 하려면 읽는 꾸러미를 먼저 넣습니다 |
| 캐릭터의 방식 | 조각(뼈대 없음) | 뼈대가 있는 캐릭터로 하면 동작 파일(서 있기, 걷기, 뛰기, 떨어지기, 날기, 손 흔들기)과 그것을 다루는 코드가 필요합니다 |
| 색 | 게임이 입힘. 재질 칸 둘까지, 텍스처 없음 | 텍스처를 쓰면 칠하기가 듣지 않는 부품이 생깁니다 |
| 모서리 | 다듬지 않은 날카로운 모서리 | 둥글리면 지금의 부품 다섯도 다시 만들어야 맞습니다 |
| 삼각형 수 | 2.5절의 값 | Quest에서 잰 뒤 다시 정합니다 |
| 시안의 "작은 집" 같은 것 | 모델이 아니라 조립품 | 모델로 만들면 한 덩어리라 안에 들어가거나 고칠 수 없습니다 |
| 제안한 것 가운데 뺄 것과 더할 것 | 정하지 않음 | 3절의 표 |

## 8. 이 문서를 고치는 방법

- 모델을 만들어 넣으면 그 줄에 넣은 일차와 출처(직접 만듦, 생성형 AI, 받은 곳과 조건)를 적습니다.
- 빼기로 한 모델은 줄을 지웁니다. 더할 모델은 묶음의 끝에 번호를 이어 붙입니다(번호는 다시 쓰지 않습니다).
- 2절의 규칙이 바뀌면 이미 만든 모델도 다시 내보내야 하는지 함께 적습니다.

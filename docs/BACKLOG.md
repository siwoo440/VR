# 앞으로 구현할 요소

2026년 10월 8일(Unity 4일차까지) 기준으로, 앞으로 넣어야 하거나 넣으면 좋을 구현 요소를 모은 문서입니다. 순서와 끝난 기준은 [`ROADMAP.md`](ROADMAP.md)가, 화면은 [`PAGES.md`](PAGES.md)가 맡고, 이 문서는 "무엇이 남았는가"를 빠짐없이 적는 데 씁니다.

표의 구분은 다음과 같습니다.

| 구분 | 뜻 |
| --- | --- |
| 필수 | 없으면 그 단계의 끝난 기준을 넘지 못합니다 |
| 권장 | 없어도 단계는 끝나지만, 있으면 눈에 띄게 좋아집니다 |
| 선택 | 여유가 있을 때 넣습니다 |
| 결정 필요 | 사용자가 정해야 만들 수 있습니다(5절) |

단계는 `ROADMAP.md` 3절의 단계(0, 1-A~1-E)입니다. "1인, 주 10시간 이하" 조건에서는 필수만으로도 1단계가 7~9개월로 잡혀 있으므로, 권장과 선택은 필수를 밀어내지 않을 때만 넣습니다.

---
## 1. 지금 있는 것

- 걷기·달리기·점프, 1인칭과 3인칭, 블록 캐릭터와 이름표
- 늘 보이는 화면(메뉴 단추, 방 정보, 사람들 목록, 부품 칸)과 Esc 메뉴(바로가기·사람들·설정·도움말)
- 블록 여섯 색을 모눈에 놓고 지우기, 놓일 자리 미리 보기, 블록 수 표시
- 개인 설정 저장(마우스 감도, 시야각, 사람들 목록 표시)
- 맵 데이터 형식 1판(`MAP-FORMAT.md`)과 이 기기의 맵 파일 하나에 자동 저장·불러오기, 화면의 저장 표시

혼자서, PC에서, 맵 하나를 이 기기에만 저장하며 쓰는 상태입니다. 계정·여러 맵·여러 사람·VR이 모두 없습니다.

---
## 2. 가장 먼저 할 것

다음 일차의 후보를 순서대로 적습니다. 위에서부터 하나씩 일차로 삼습니다.

1. **실행 취소**(3.1): 실수로 지운 블록을 되살릴 방법이 없습니다. 만들기 도구가 늘기 전에 넣어야 뒤의 도구가 모두 되돌리기를 지원합니다.
2. **블록 칠하기와 알림 띠**(3.1, 3.9): 지우고 다시 놓지 않고 색을 바꾸고, "놓을 수 없습니다"나 "블록 N개를 읽지 못했습니다"를 띠로 알려 줍니다. 지금은 오른쪽 아래의 작은 저장 표시뿐입니다.
3. **만들기 시점**(3.1): 날아다니며 만드는 시점이 없어 높은 곳은 쌓아 올라가야 합니다.
4. **Windows 빌드 확인**(3.11): 아직 한 번도 빌드하지 않았습니다. 에디터 밖에서 도는지, 저장 폴더가 실제로 만들어지는지 일찍 확인합니다.
5. **조작과 겉모습 나누기**(3.5): VR 캐릭터와 다른 사람의 캐릭터를 넣기 전에 해야 하는 구조 정리입니다.
6. **VR 리그와 Quest 빌드, 성능 재기**(3.3, 3.4): Android 빌드 구성이 설치된 뒤에 합니다. 부품 수 상한과 블록을 그리는 방식이 여기서 정해집니다.
7. **모양이 다른 부품과 부품 고르는 창**(3.1): 정육면체 여섯 색만으로는 만들 수 있는 것이 적습니다. 데이터 형식에는 방향(`facing`) 자리를 두었습니다.
8. **여러 맵 다루기**(3.2): 지금은 이 기기에 맵 파일이 하나뿐입니다.

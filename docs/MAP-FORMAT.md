# 맵 데이터 형식

맵 하나를 파일로 저장할 때의 형식입니다. 2026년 10월 8일(Unity 4일차)에 형식 1판을 정했습니다. 사업 계획서 12.2.2의 "부품 + 속성 + 동작"을 따르며, 조립품과 동작 규칙은 자리만 두고 내용은 뒤 단계에서 채웁니다.

한 번 공개한 뒤에는 형식을 마음대로 바꿀 수 없습니다. 바꿀 때는 `version`을 올리고 옛 판을 읽는 길을 함께 만듭니다(아래 5절).

---
## 1. 원칙

- 블록은 부품의 **번호가 아니라 저장용 이름(`part`)**으로 적습니다. 부품 칸의 순서가 바뀌어도 파일은 그대로 읽힙니다. 저장용 이름은 `PartCatalog`의 `id`이며 한 번 정하면 바꾸지 않습니다.
- 파일 하나가 맵 하나입니다. 사람이 읽을 수 있는 JSON이며 글자 인코딩은 UTF-8입니다.
- 읽을 때는 파일을 믿지 않습니다. 형식 이름, 판 번호, 범위, 개수 상한, 모르는 부품, 같은 칸의 중복을 검사하고 문제가 있는 블록은 건너뛰며 그 수를 돌려줍니다.
- 날짜와 시각은 UTC의 ISO 8601(`2026-10-08T03:51:00Z`)로 적습니다.

---
## 2. 구조 (1판)

```json
{
  "format": "atelier-verse-map",
  "version": 1,
  "name": "시험 작업실",
  "createdAt": "2026-10-08T03:51:00Z",
  "updatedAt": "2026-10-08T04:12:30Z",
  "bounds": { "min": { "x": -8, "y": 0, "z": -8 }, "max": { "x": 7, "y": 11, "z": 7 } },
  "blocks": [
    { "part": "block.gold", "cell": { "x": 2, "y": 0, "z": 2 }, "facing": 0 },
    { "part": "block.blue", "cell": { "x": -5, "y": 0, "z": 1 }, "facing": 0 }
  ],
  "assemblies": [],
  "rules": []
}
```

| 항목 | 종류 | 내용 |
| --- | --- | --- |
| `format` | 글 | 항상 `atelier-verse-map`. 다른 값이면 이 서비스의 맵 파일이 아닙니다 |
| `version` | 정수 | 형식의 판 번호. 지금은 `1` |
| `name` | 글 | 맵 이름. 비어 있으면 화면에서는 "이름 없는 맵"으로 보입니다 |
| `createdAt`, `updatedAt` | 글 | 처음 만든 시각과 마지막으로 저장한 시각 |
| `bounds` | 칸 두 개 | 놓을 수 있는 범위. `min`과 `max`를 포함하는 닫힌 범위입니다 |
| `blocks` | 목록 | 놓인 블록. 순서는 뜻이 없습니다 |
| `assemblies` | 목록 | 조립품 자리. 2단계에서 정의하며 지금은 항상 비어 있습니다 |
| `rules` | 목록 | 동작 규칙 자리. 3단계에서 정의하며 지금은 항상 비어 있습니다 |

### 2.1 블록 하나

| 항목 | 종류 | 내용 |
| --- | --- | --- |
| `part` | 글 | 부품의 저장용 이름(`block.gold` 등) |
| `cell` | 칸 | 블록이 차지하는 칸. 모눈 한 칸이 1m이고 `cell`의 가운데가 블록의 가운데입니다 |
| `facing` | 정수 | 바라보는 방향. `0`은 +z, 이후 시계 방향으로 `1`은 +x, `2`는 -z, `3`은 -x. 정육면체뿐인 지금은 항상 `0`이며, 경사·계단처럼 모양이 있는 부품이 생기면 씁니다 |

부품별 속성(색 바꾸기 등)이 필요해지면 블록에 항목을 더하고 판 번호를 올립니다. 1판에는 없습니다.

### 2.2 칸

`{ "x": 정수, "y": 정수, "z": 정수 }`입니다. `y`가 높이입니다. Unity의 `Vector3Int`를 그대로 직렬화한 모양입니다.

## 3. 읽을 때의 검사

| 검사 | 문제가 있을 때 |
| --- | --- |
| `format`이 `atelier-verse-map`이 아님 | 파일 전체를 거부합니다 |
| `version`이 지금 판보다 큼 | 파일 전체를 거부합니다(새 판의 앱에서 만든 파일) |
| `version`이 지금 판보다 작음 | 옛 판을 읽는 길로 바꿔 읽습니다(5절) |
| JSON이 깨짐 | 파일 전체를 거부합니다 |
| 블록의 `part`가 부품 목록에 없음 | 그 블록만 건너뜁니다 |
| 블록의 `cell`이 범위 밖 | 그 블록만 건너뜁니다 |
| 같은 칸에 블록이 둘 | 뒤의 것을 건너뜁니다 |
| 블록 수가 상한을 넘음 | 상한까지만 읽고 나머지를 건너뜁니다 |
| `facing`이 0~3 밖 | `0`으로 읽습니다 |

건너뛴 수는 불러온 결과에 담아 화면에서 "블록 N개를 읽지 못했습니다"처럼 알립니다. 파일의 `bounds`는 참고용이며, 실제 범위는 앱의 블록 세계가 정합니다. 뒤에 맵마다 크기를 다르게 두게 되면 파일의 값을 쓰도록 바꿉니다.

## 4. 저장 위치 (이 기기)

| 구분 | 위치 |
| --- | --- |
| 폴더 | `Application.persistentDataPath/maps/` (Windows에서는 `%USERPROFILE%\AppData\LocalLow\Palettra Games\Atelier Verse\maps\`) |
| 파일 | `local.map.json`. 맵이 여럿이 되면(1-A의 "여러 맵 다루기") 맵마다 파일 하나로 늘립니다 |
| 쓰는 방법 | 임시 파일(`*.tmp`)에 먼저 쓰고 이름을 바꿉니다. 쓰는 도중 꺼져도 이전 파일이 남습니다 |

자동 저장은 블록이 바뀌고 잠시 뒤(1초)와 앱을 끝낼 때 합니다. 저장에 실패하면 화면에 알리고 다음 변경 때 다시 시도합니다.

계정에 저장하는 것(1-C)은 같은 JSON을 그대로 올리는 것으로 시작합니다.

---
## 5. 판을 올리는 방법

1. 이 문서의 2절에 새 판의 구조를 적고 바뀐 항목을 표로 남깁니다.
2. `MapDocument.CurrentVersion`을 올립니다.
3. `MapDocument.Upgrade`에 옛 판을 새 판으로 바꾸는 단계를 더합니다. 판은 한 단계씩 올립니다(1 → 2 → 3).
4. 옛 판 파일을 테스트 자료로 두고 새 판으로 읽히는지 검사합니다(`MapDocumentTests`).

형식을 바꾸지 않고 항목만 더할 때도 판 번호를 올립니다. 옛 앱이 새 파일을 읽지 못하게 해야 뜻을 모르는 항목을 버리고 저장하는 일을 막을 수 있습니다.

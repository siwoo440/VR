# 맵 데이터 형식

맵 하나를 파일로 저장할 때의 형식입니다. 지금 판은 **4판**입니다(2026년 10월 10일, Unity 23일차). 사업 계획서 12.2.2의 "부품 + 속성 + 동작"을 따르며, 조립품과 동작 규칙은 자리만 두고 내용은 뒤 단계에서 채웁니다.

한 번 공개한 뒤에는 형식을 마음대로 바꿀 수 없습니다. 바꿀 때는 `version`을 올리고 옛 판을 읽는 길을 함께 만듭니다(아래 5절).

| 판 | 정한 날 | 내용 |
| --- | --- | --- |
| 1판 | 2026-10-08(4일차) | 모눈의 칸 번호(`cell`)와 방향(`facing` 0~3). 칸 하나에 블록 하나 |
| 2판 | 2026-10-09(14일차) | 고유 번호(`id`), 가운데의 자리(`position`), 방향(`rotation`). 칸에 맞추지 않고 어디에나 놓임 |
| 3판 | 2026-10-10(18일차) | 블록은 2판과 같음. 맵의 설명(`description`)과 시작 위치(`spawn`)가 더해짐 |
| 4판 | 2026-10-10(23일차) | 블록은 2판과 같음. 맵의 분위기(`environment`: 하늘, 해의 방향과 높이)가 더해지고, 범위(`bounds`)가 맵마다의 바닥 크기를 정함 |

2판은 "맵의 요소는 칸에 맞추지 않고 자유롭게 배치한다. 길이의 표준은 블록 하나의 1×1×1이다"라는 결정(2026-10-09)에 따라 만들었습니다.

---
## 1. 원칙

- 블록은 부품의 **번호가 아니라 저장용 이름(`part`)**으로 적습니다. 부품 칸의 순서가 바뀌어도 파일은 그대로 읽힙니다. 저장용 이름은 `PartCatalog`의 `id`이며 한 번 정하면 바꾸지 않습니다.
- 블록은 **칸이 아니라 자리**로 적습니다. 자리는 블록 가운데의 좌표이고 소수입니다.
- **길이의 표준은 표준 블록 한 변 = 1**이며 Unity의 1m와 같습니다. 부품의 크기와 맵의 범위를 모두 이 단위로 적습니다.
- 블록마다 **고유 번호(`id`)**가 있습니다. 되돌리기, 뒤 단계의 여러 사람 접속과 동작 규칙이 블록을 번호로 가리킵니다.
- 파일 하나가 맵 하나입니다. 사람이 읽을 수 있는 JSON이며 글자 인코딩은 UTF-8입니다.
- 읽을 때는 파일을 믿지 않습니다. 형식 이름, 판 번호, 범위, 개수 상한, 모르는 부품, 같은 자리의 중복을 검사하고 문제가 있는 블록은 건너뛰며 그 수를 돌려줍니다.
- 날짜와 시각은 UTC의 ISO 8601(`2026-10-08T03:51:00Z`)로 적습니다.

## 2. 구조 (4판)

```json
{
  "format": "atelier-verse-map",
  "version": 4,
  "name": "시험 작업실",
  "description": "집과 계단이 있는 처음의 맵",
  "createdAt": "2026-10-08T03:51:00Z",
  "updatedAt": "2026-10-09T04:12:30Z",
  "bounds": { "min": { "x": -8.0, "y": 0.0, "z": -8.0 }, "max": { "x": 8.0, "y": 12.0, "z": 8.0 } },
  "spawn": { "custom": true, "position": { "x": -2.5, "y": 0.0, "z": -4.5 }, "yaw": 40.0 },
  "environment": { "sky": "day", "sunYaw": 330.0, "sunPitch": 50.0 },
  "blocks": [
    { "id": 1, "part": "block.gold", "position": { "x": 2.5, "y": 0.5, "z": 2.5 }, "rotation": { "x": 0.0, "y": 0.0, "z": 0.0 } },
    { "id": 2, "part": "block.blue", "position": { "x": -4.37, "y": 0.5, "z": 1.82 }, "rotation": { "x": 0.0, "y": 30.0, "z": 0.0 } }
  ],
  "assemblies": [],
  "rules": []
}
```

| 항목 | 종류 | 내용 |
| --- | --- | --- |
| `format` | 글 | 항상 `atelier-verse-map`. 다른 값이면 이 서비스의 맵 파일이 아닙니다 |
| `version` | 정수 | 형식의 판 번호. 지금은 `4` |
| `name` | 글 | 맵 이름. 비어 있으면 화면에서는 "이름 없는 맵"으로 보입니다 |
| `description` | 글 | 맵의 설명. 한 줄이고 80자까지. 없으면 빈 글자(3판) |
| `createdAt`, `updatedAt` | 글 | 처음 만든 시각과 마지막으로 저장한 시각 |
| `bounds` | 좌표 두 개 | 놓을 수 있는 범위인 상자의 두 모서리(`min`, `max`). 블록은 이 상자 안에 다 들어와야 합니다. 4판부터 맵마다의 바닥 크기를 정합니다(2.5절) |
| `spawn` | 묶음 | 캐릭터가 처음 서는 자리(3판). 아래 2.4절 |
| `environment` | 묶음 | 맵의 분위기(4판). 아래 2.5절 |
| `blocks` | 목록 | 놓인 블록. 번호 순으로 적지만 순서에는 뜻이 없습니다 |
| `assemblies` | 목록 | 조립품 자리. 2단계에서 정의하며 지금은 항상 비어 있습니다 |
| `rules` | 목록 | 동작 규칙 자리. 3단계에서 정의하며 지금은 항상 비어 있습니다 |

### 2.1 블록 하나

| 항목 | 종류 | 내용 |
| --- | --- | --- |
| `id` | 정수 | 블록의 고유 번호. 1부터이고 맵 안에서 겹치지 않습니다. 지운 블록의 번호는 다시 쓰지 않습니다 |
| `part` | 글 | 부품의 저장용 이름(`block.gold` 등) |
| `position` | 좌표 | 블록 **가운데**의 자리. 1mm(0.001) 단위로 다듬어 적습니다 |
| `rotation` | 각도 세 개 | x·y·z 축으로 돈 각도(도). `y`가 위에서 보아 시계 방향으로 도는 좌우 방향입니다. 돌리지 않았으면 모두 `0` |

- 블록끼리는 **겹쳐도 됩니다.** 다만 가운데가 정확히(1mm 안으로) 같은 자리에는 블록을 둘 두지 않습니다.
- 부품마다 모양과 크기가 정해져 있습니다(2.3절). 크기는 블록 한 변 1을 기준으로 하며, 파일에는 적지 않고 부품의 이름으로 압니다.
- 앱은 블록을 좌우로만 돌립니다(15일차, 15도씩). `rotation`의 `x`와 `z`는 지금 항상 `0`이며, 기울이기를 넣을 때를 위해 자리를 두었습니다.

부품별 속성(색 바꾸기 등)이 필요해지면 블록에 항목을 더하고 판 번호를 올립니다. 2판에는 없습니다.

### 2.2 좌표와 길이

좌표는 `{ "x": 소수, "y": 소수, "z": 소수 }`입니다. `y`가 높이입니다. 단위는 표준 블록 한 변(= 1m)입니다. Unity의 `Vector3`를 그대로 직렬화한 모양입니다.

바닥은 `y = 0`이고, 바닥에 얹은 표준 블록의 가운데는 `y = 0.5`입니다. 높이가 반인 판을 바닥에 얹으면 가운데는 `y = 0.25`입니다. 모눈 바닥의 선은 1 간격이라 길이를 재는 자로 쓸 수 있습니다.

### 2.3 부품의 이름 (16일차)

부품의 이름은 `모양.색`입니다. 형식의 판은 그대로 2판이고 이름만 늘었습니다.

| 모양 | 이름의 앞부분 | 크기(가로 × 높이 × 세로) | 내용 |
| --- | --- | --- | --- |
| 블록 | `block` | 1 × 1 × 1 | 표준 블록. 14일차까지의 부품은 모두 이것입니다 |
| 판 | `slab` | 1 × 0.5 × 1 | 높이가 반 |
| 기둥 | `pillar` | 0.5 × 1 × 0.5 | 굵기가 반 |
| 경사 | `wedge` | 1 × 1 × 1 | 45도. 돌리지 않았을 때 `-z` 쪽 바닥에서 `+z` 쪽 꼭대기로 오릅니다 |
| 계단 | `stairs` | 1 × 1 × 1 | 네 단. 오르는 방향은 경사와 같습니다 |

색은 `gold`, `blue`, `clay`, `leaf`, `ivory`, `wood`의 여섯입니다(예: `slab.gold`, `stairs.wood`).

- `position`은 부품을 둘러싸는 상자의 가운데입니다. 범위는 부품의 크기로 봅니다(방향은 보지 않습니다).
- 앱이 모르는 이름의 부품은 건너뜁니다(3절). 16일차보다 앞의 앱은 블록만 알고 있으므로, 새 부품이 든 맵을 옛 앱으로 열어 저장하면 그 부품이 사라집니다.
- 색을 부품에서 떼어 블록의 항목으로 두게 되면 판 번호를 올립니다.

### 2.4 시작 위치 (18일차)

| 항목 | 종류 | 내용 |
| --- | --- | --- |
| `custom` | 참·거짓 | 시작 위치를 따로 정했는지. `false`이면 정한 것이 없으며 앱의 처음 자리에서 시작합니다 |
| `position` | 좌표 | 캐릭터의 **발이 닿는 자리**. `custom`이 `true`일 때만 뜻이 있습니다 |
| `yaw` | 소수 | 시작할 때 바라보는 좌우 각도(도, 0 이상 360 미만). 블록의 `rotation.y`와 같은 방향입니다 |

- 시작 위치는 맵의 범위(`bounds`의 상자) 안에서만 정합니다.
- 값이 숫자가 아니면 정하지 않은 것으로 읽습니다.
- 시작 위치에 블록이 놓여 막혀 있으면, 앱은 그 위쪽의 빈 자리에 캐릭터를 세웁니다. 파일의 값은 바꾸지 않습니다.
- 맵의 대표 그림은 파일 안에 넣지 않고 맵 파일 옆에 그림 파일로 둡니다(4절).

### 2.5 분위기와 바닥 크기 (23일차)

| 항목 | 종류 | 내용 |
| --- | --- | --- |
| `environment.sky` | 글 | 하늘의 이름. `day`(맑은 낮), `sunset`(노을), `night`(밤), `cloudy`(흐림) 가운데 하나. 하늘의 색, 햇빛의 색과 세기, 그늘의 밝기는 이름마다 앱이 정해 둔 값입니다 |
| `environment.sunYaw` | 소수 | 해의 방향(도, 0 이상 360 미만). 햇빛이 가는 쪽이며 블록의 `rotation.y`와 같은 방향입니다. 앱은 15도씩 고릅니다 |
| `environment.sunPitch` | 소수 | 해의 높이(도, 10~90). 90이면 머리 위에서 곧게 내려옵니다. 앱은 5도씩 고릅니다 |

- 정하지 않은 맵의 값은 `day`, `330`, `50`입니다. 3판까지의 모습과 같습니다.
- 모르는 하늘의 이름은 `day`로, 범위를 벗어난 각도는 범위 안으로, 숫자가 아닌 값은 처음 값으로 읽습니다.
- 바닥의 크기는 따로 적지 않고 `bounds`로 압니다. 앱이 고르는 크기는 한 변 16, 24, 32이며, 범위는 가운데(0, 0)에서 양쪽으로 변의 반씩이고 높이는 0~12입니다. 파일의 범위가 이 셋이 아니면 가로 길이가 가장 가까운 크기로 읽습니다.
- 바닥을 줄일 때 새 범위 밖에 블록이나 시작 위치가 남으면 앱은 줄이지 않습니다. 파일을 직접 고쳐 범위를 줄이면 밖의 블록은 읽을 때 건너뜁니다(3절).
- 하늘의 이름이 늘어나도 판은 그대로입니다(부품의 이름과 같습니다). 다만 그 이름을 모르는 앱으로 열어 저장하면 `day`로 바뀝니다.

## 3. 읽을 때의 검사

| 검사 | 문제가 있을 때 |
| --- | --- |
| `format`이 `atelier-verse-map`이 아님 | 파일 전체를 거부합니다 |
| `version`이 지금 판보다 큼 | 파일 전체를 거부합니다(새 판의 앱에서 만든 파일) |
| `version`이 지금 판보다 작음 | 옛 판을 읽는 길로 바꿔 읽습니다(5절) |
| JSON이 깨짐 | 파일 전체를 거부합니다 |
| 블록의 `part`가 부품 목록에 없음 | 그 블록만 건너뜁니다 |
| 블록이 범위 안에 다 들어오지 않음 | 그 블록만 건너뜁니다 |
| 가운데가 같은 자리에 블록이 둘 | 뒤의 것을 건너뜁니다 |
| 블록 수가 상한을 넘음 | 상한까지만 읽고 나머지를 건너뜁니다 |
| `id`가 없거나(1보다 작음) 앞의 블록과 같음 | 건너뛰지 않고 **새 번호를 붙여** 읽습니다 |
| `environment`가 없거나 값이 바르지 않음 | 거부하지 않고 다듬어 읽습니다(2.5절) |

건너뛴 수는 불러온 결과에 담아 화면에서 "블록 N개를 읽지 못했습니다"처럼 알립니다. 4판부터 범위는 파일의 `bounds`가 정합니다(가장 가까운 바닥 크기로 읽음, 2.5절). 3판까지는 참고용이었고 모든 맵이 같은 범위였습니다.

## 4. 저장 위치 (이 기기)

| 구분 | 위치 |
| --- | --- |
| 폴더 | `Application.persistentDataPath/maps/` (Windows에서는 `%USERPROFILE%\AppData\LocalLow\Palettra Games\Atelier Verse\maps\`) |
| 파일 | 맵마다 하나, `번호표.map.json`(17일차). 번호표는 영문 소문자·숫자·줄표이며 한 번 정하면 바뀌지 않습니다(맵의 이름을 바꿔도 그대로). 처음부터 있던 맵은 `local.map.json`이고, 새로 만든 맵은 만든 시각으로 짓습니다(`map-20261010-103000.map.json`) |
| 쓰는 방법 | 임시 파일(`*.tmp`)에 먼저 쓰고 이름을 바꿉니다. 쓰는 도중 꺼져도 이전 파일이 남습니다 |
| 옛 판의 사본 | 옛 판의 파일을 읽으면 원래 파일을 `local.map.json.v2.bak`처럼 옆에 남기고(읽은 파일의 판 번호가 붙음), 곧 지금 판으로 다시 저장합니다. 사본이 이미 있으면 덮어쓰지 않습니다 |
| 읽지 못한 파일 | 시작할 때 연 맵이 읽히지 않으면 `local.map.json.broken-시각`처럼 옮겨 둡니다. 맵 목록에서 고른 맵이 읽히지 않으면 열지 않고 파일도 그대로 둡니다 |
| 마지막으로 연 맵 | `current.txt`에 번호표를 적습니다. 처음부터 있던 맵뿐일 때는 만들지 않습니다. 적힌 맵이 없어졌으면 처음부터 있던 맵을, 그것도 없으면 가장 최근에 저장한 맵을 엽니다 |
| 지운 맵 | 없애지 않고 `trash/번호표-지운 시각.map.json`으로 옮깁니다. 이 파일을 다시 `maps` 폴더로 옮기면 맵 목록에 나옵니다 |
| 대표 그림 | `번호표.png`(480×270, 18일차). 맵 파일 안이 아니라 옆에 둡니다. 없어도 맵은 열립니다. 지운 맵의 그림은 휴지통의 맵 파일 옆으로 함께 옮깁니다 |
| 맵의 수 | 50개까지. 목록을 볼 때 폴더의 맵 파일을 모두 읽습니다 |

자동 저장은 블록이 바뀌고 잠시 뒤(1초)와 앱을 끝낼 때 합니다. 저장에 실패하면 화면에 알리고 다음 변경 때 다시 시도합니다.

계정에 저장하는 것(1-C)은 같은 JSON을 그대로 올리는 것으로 시작합니다.

## 5. 판을 올리는 방법

1. 이 문서의 2절에 새 판의 구조를 적고 바뀐 항목을 표로 남깁니다.
2. `MapDocument.CurrentVersion`을 올립니다.
3. 옛 판을 새 판으로 바꾸는 단계를 `MapDocument`에 더합니다. 블록의 모양이 바뀌면 옛 판의 구조를 따로 두고(`MapDocumentV1`처럼) 그것으로 읽은 뒤 바꿉니다. 판은 한 단계씩 올립니다(1 → 2 → 3 → 4).
4. 옛 판 파일을 테스트 자료로 두고 새 판으로 읽히는지 검사합니다(`MapDocumentTests`, `SavePlayTests`).

형식을 바꾸지 않고 항목만 더할 때도 판 번호를 올립니다. 옛 앱이 새 파일을 읽지 못하게 해야 뜻을 모르는 항목을 버리고 저장하는 일을 막을 수 있습니다.

### 5.1 1판을 2판으로 올리는 규칙

| 1판 | 2판 |
| --- | --- |
| 블록의 `cell`(칸 번호) | `position` = 칸의 가운데. 칸 `(x, y, z)`는 `(x + 0.5, y + 0.5, z + 0.5)` |
| 블록의 `facing`(0~3) | `rotation.y` = `facing × 90`. 0~3 밖의 값은 0 |
| 번호 없음 | 파일에 적힌 순서대로 `id`를 1부터 붙임 |
| `bounds`(칸 번호의 범위, 두 끝을 포함) | 가장 작은 칸의 아래 모서리부터 가장 큰 칸의 위 모서리까지의 상자. `max`에 1을 더함 |

1판에서 놓을 수 있던 칸은 2판의 범위에도 모두 들어옵니다. 올려 읽은 맵은 화면에서 전과 똑같이 보입니다.

### 5.2 2판을 3판으로 올리는 규칙

| 2판 | 3판 |
| --- | --- |
| 블록, 이름, 시각, 범위 | 그대로 |
| `description` 없음 | 빈 글자 |
| `spawn` 없음 | `custom`이 `false`(정하지 않음). 전처럼 앱의 처음 자리에서 시작 |

올려 읽은 맵은 전과 똑같이 보이고 같은 자리에서 시작합니다. 17일차까지의 앱은 3판의 파일을 읽지 못합니다.

### 5.3 3판을 4판으로 올리는 규칙

| 3판 | 4판 |
| --- | --- |
| 블록, 이름, 설명, 시각, 시작 위치 | 그대로 |
| `environment` 없음 | `sky`는 `day`, `sunYaw`는 `330`, `sunPitch`는 `50` |
| `bounds`(참고용) | 값은 그대로이고 이제 바닥 크기로 씁니다. 3판의 맵은 모두 한 변 16입니다 |

올려 읽은 맵은 전과 똑같이 보입니다(22일차와 23일차의 실행 파일이 찍은 그림을 점마다 견주어 확인). 22일차까지의 앱은 4판의 파일을 읽지 못합니다.

# 점검 결과와 구현 단계

2026년 10월 8일 기준으로 지금까지 만든 것을 점검하고, 구현을 어떤 순서로 진행할지 정리한 문서입니다. 기간과 끝난 기준의 숫자는 모두 "1인, 주 10시간 이하" 조건에서 잡은 가안이며 실제로 재 본 값이 아닙니다.

같은 날 구현 방식을 바꿨습니다. 처음에는 브라우저(WebXR)로 만들기로 했다가, **Unity 앱 하나로 PC(Windows)와 VR(Meta Quest)을 함께 지원**하기로 했습니다. 이 문서는 바뀐 방식 기준입니다.

## 2. 부족한 부분

급한 순서로 적습니다.

### 2.1 서비스의 핵심이 검증되지 않았다

아래 세 가지 가운데 하나라도 안 되면 기획을 바꿔야 합니다.

1. **Quest 기기 성능**: Quest에서 블록 공간이 끊김 없이 도는지 확인하지 않았습니다. 시안의 "부품 2,000개" 상한은 근거 없이 적은 숫자입니다.
2. **여러 사람 동기화**: 8명이 같은 방에서 움직일 때의 방식과 서버 비용을 정하지 않았습니다.
3. **에디터 조작감**: 부품을 놓고 옮기는 조작이 쉬운지는 직접 만들어 써 봐야 압니다.

### 2.2 기획에 비어 있는 결정

- **VR의 실제 기기 확인**: VR 조작과 추적(10일차), OpenXR 연결(11일차), VR 메뉴(12일차), VR에서 만들기(13일차)를 만들었지만 실제 헤드셋으로 확인하지 못했습니다(이 컴퓨터에 VR 프로그램이 없음).
- **앱과 웹의 경계**: 에디터와 방 안은 앱에 있습니다. 내 작업실, 둘러보기, 소식 같은 화면을 앱 안에 둘지 웹에 둘지 정하지 않았습니다.
- **앱 배포 방법**: PC용 앱을 어디서 내려받게 할지, Quest용 앱을 어떻게 설치하게 할지(스토어 심사 포함) 정하지 않았습니다.
- **범위가 조건에 비해 넓다**: 시안에 그린 메시지(그룹·공지 채널), 상점, 구독, 제작자 마켓까지 가면 몇 해가 걸립니다.
- **성공 기준이 없다**: 비공개 시험에서 무엇을 보면 계속하고 무엇을 보면 멈출지 정하지 않았습니다.

### 2.3 화면 시안

- **VR 안의 화면이 일부만 있다**: 메뉴와 알림은 12일차에 눈앞의 판으로, 부품 칸과 걷기·날기 표시는 13일차에 왼손 위의 부품 판으로 띄웠습니다(가상 기기로만 확인). 이동 표시와 채팅 보기는 아직 없습니다. PC용 게임 화면은 2일차에 Unity에서 만들었고(`unity/Devlogs/Day02`), VR은 같은 화면을 판으로 띄우는 방식입니다.
- **빠진 화면**(같은 날 보완): 처음 안내, 설정, 알림 목록, 검색 결과, 상태 화면, 운영자용 신고 처리 화면을 추가했습니다. 에디터와 방 안의 세부 흐름, 결제 화면은 아직 없습니다(`docs/PAGES.md` 5절).
- **탭 구조와 누르기 크기**(같은 날 보완): 탭과 내용을 짝짓고, 손가락으로 누르는 화면에서 작은 요소를 44px로 키웠습니다.
- **앱 화면과 웹 화면이 섞여 있다**: 에디터와 방 안 시안은 웹 화면으로 그렸지만 실제로는 Unity 화면이 됩니다. 배치와 문구의 기준으로만 씁니다.
- **실제 기기에서 보지 않았다**: 웹 화면은 브라우저 너비만 바꿔 확인했습니다.
- **영어 화면이 없다**.

### 2.4 통합 계정

- **실제로 동작한 적이 없다**: Supabase 화면 설정과 Mate | Verse 쪽 작업이 남았습니다.
- **앱에서의 로그인 방법이 정해지지 않았다**: 앱은 기기의 브라우저를 열어 로그인한 뒤 앱으로 돌아오는 방식이 필요합니다. Quest에서의 동작은 확인이 필요합니다.
- **베타 기능에 기댄다**: 홈페이지를 로그인 제공자로 만드는 Supabase 기능이 베타입니다.
- **약관과 개인정보처리방침**에 통합 계정 내용이 없습니다.

### 2.5 운영과 법률

- 한국에서 이용자 제작 플랫폼이 게임물 등급 분류 대상인지 확인하지 못했습니다. 설치형 앱으로 배포하면 이 문제가 더 직접적입니다.
- 만 14세 이상 확인 방법, 결제·환불, 사업자 신고, 상표·도메인, 월 운영비가 모두 미정입니다.
- 이용자가 만든 것을 혼자서 관리할 방법과 시간이 계산되지 않았습니다.

### 2.6 이 컴퓨터의 준비 상태

- Unity 6000.3.21f1에 Windows 빌드 구성만 있습니다. Windows 빌드는 8일차에 명령줄로 만들어 실행까지 확인했습니다. Quest용으로 만들려면 Unity Hub에서 Android 빌드 구성을 추가로 설치해야 합니다.
- Quest를 PC에 연결하는 프로그램이 설치되어 있지 않습니다.

## 3. 구현 단계

원칙은 세 가지입니다.

- 안 될 수 있는 것부터 작게 확인합니다.
- 단계마다 "끝난 기준"을 정하고, 기준을 넘지 못하면 다음으로 가지 않습니다.
- 1단계가 끝나기 전에는 상점·구독·메시지 같은 뒤 단계 기능을 만들지 않습니다.

Unity 작업은 일차 단위로 진행하고 `unity/Devlogs/DayNN/README.md`에 그날의 일지를 남깁니다. 단계마다 무엇을 만들어야 하는지의 자세한 목록은 [`BACKLOG.md`](BACKLOG.md)에 있습니다.

### 3.1 단계별 메모

**0단계**
- 1일차에 프로젝트와 PC 조작을, 2일차에 블록 캐릭터와 1인칭·3인칭 시점, 게임 화면을 만들었습니다. 3일차에 부품 칸에서 고른 블록을 모눈에 놓고 지우는 것을, 4일차에 맵 데이터 형식(`docs/MAP-FORMAT.md`)과 이 기기에 자동 저장·불러오기를, 5일차에 놓기·지우기의 되돌리기와 다시 실행을, 6일차에 블록 칠하기와 알림 띠를, 7일차에 날기(만들기 시점)와 걸어 보기의 전환을, 8일차에 Windows 빌드 스크립트를 만들어 실제로 빌드하고 실행해 확인했습니다. 9일차에 캐릭터를 몸·카메라 리그·PC 조작으로 나눠 VR 캐릭터와 다른 사람의 캐릭터를 넣을 자리를 만들었습니다. 10일차에 VR 조작과 추적 리그를 만들어 가상 기기로 확인했습니다. 11일차에 OpenXR 패키지를 넣어, 실행할 때 `-vr`을 주었을 때만 VR 화면을 켜게 했습니다. 기기가 없는 PC에서 키보드·마우스로 돌아오는 것까지 확인했습니다. 12일차에 VR에서 화면을 눈앞의 판으로 띄우고 오른손 광선으로 누르게 했으며 가상 기기로 확인했습니다. 13일차에 VR에서 오른손으로 가리켜 블록을 놓고 지우고 칠하게 했고 왼손 위의 부품 판을 만들었으며 가상 기기로 확인했습니다. 14일차에 맵의 요소를 칸에 맞추지 않고 자유롭게 놓게 바꿨습니다(블록을 번호와 자리로 기록, 맵 형식 2판, 옛 파일은 올려 읽음). 15일차에 놓을 블록을 돌리고, 놓인 블록을 옮기고, 맞추기 도우미로 반듯하게 놓게 했습니다(VR은 가상 기기로 확인). 16일차에 판·기둥·경사·계단과 부품 고르는 창을 넣었습니다(VR은 가상 기기로 확인). 17일차에 맵을 여러 개 만들고 맵 목록에서 골라 열 수 있게 했습니다. 18일차에 맵마다 시작 위치를 정하고 맵 정보(설명, 대표 그림)를 넣었습니다(맵 형식 3판). 19일차에 기본 소리(걷기·블록·단추·알림의 소리 22가지와 소리 크기 설정)를 넣었습니다. 소리는 코드로 만들었고 귀로 들어 보는 확인은 사용자가 해야 합니다. 20일차에 설정을 화면·조작·소리 갈래로 나누고 화면 방식(창·전체 화면), 화면 품질 세 단계, 수직 동기화, 위아래 시점 반대로를 넣었습니다(실행 파일에서 품질과 전체 화면이 되는 것을 로그로 확인). 다음은 끌어서 여러 개 놓기, 그리고 실제 헤드셋으로 확인하는 일(사용자가 Quest Link나 SteamVR을 설치한 뒤)입니다. Quest 단독 빌드는 Android 빌드 구성이 설치된 뒤에 합니다.
- 3일차의 블록 수 상한 500개와 블록 하나를 게임 오브젝트 하나로 두는 방식은 임시입니다.
- 부품 상한은 Quest에서 잰 값으로 정합니다.
- 동기화 방식은 작은 시험으로 정합니다. Unity의 기본 도구(Netcode for GameObjects와 중계 서비스)를 먼저 살펴보고 8명 방에서의 비용과 한도를 확인합니다.
- PC의 키보드·마우스가 기본이고, VR 기기가 있으면 추적과 장비로 할 수 있는 기능이 되게 합니다(2026-10-08 결정). 순서는 추적과 이동(10일차) → 실제 기기 연결(11일차, 헤드셋 확인 전) → VR 메뉴(12일차) → VR에서 만들기(13일차)입니다.

**1-A**
- 시안의 에디터 화면을 배치 기준으로 삼되, 써 보고 불편하면 바꿉니다.

## 5. 정해진 것과 남은 질문

2026-10-08에 정해진 것입니다.

- Unity 앱 하나로 PC와 VR을 함께 지원한다.
- VR 기기는 Meta Quest이며 시험할 기기가 있다.
- Unity 프로젝트는 이 저장소의 `unity/` 폴더에 둔다.
- 일차별 개발 일지와 "N일차 : 내용" 커밋으로 진행한다.
- 게임 화면은 로블록스와 VRChat을 섞는다. 늘 보이는 화면은 로블록스처럼 위쪽 띠·사람들 목록·아래쪽 부품 칸으로 두고, Esc 메뉴는 로블록스의 탭과 아래 단추에 VRChat의 큰 타일과 머리 위 이름표를 더한다.
- 게임 화면은 Unity의 uGUI로 만든다. VR에서 같은 화면을 눈앞에 띄우는 방법이 가장 널리 검증되어 있기 때문이다.
- PC에서 키보드·마우스로 쓰는 것이 기본이다. VRChat처럼 VR 기기가 있는 사람은 추적과 장비로 할 수 있는 기능이 되게 한다. "VR에서는 구경과 이동만"이라는 앞의 기본안을 대체한다.

2026-10-09에 정해진 것입니다.

- 맵의 요소는 칸(블록)에 맞추지 않고 자유롭게 배치한다. 길이의 표준은 블록 하나의 1×1×1이다. 3일차부터의 "칸 하나에 블록 하나" 구조를 대체한다.

남은 질문입니다.

1. 내 작업실, 둘러보기, 소식 같은 화면을 앱 안에 둘 것인가 웹에 둘 것인가.
2. 1단계가 끝날 때까지 뒤 단계 기능(메시지, 상점, 구독)을 만들지 않는 데 동의하는가.
3. 1-E의 판단 기준을 위 가안대로 둘 것인가.
